# Pool Practice Overlay — notes for Claude

Windows overlay (PySide6 + OpenCV + mss) for Miniclip 8 Ball Pool mirrored from an iPhone through an AirPlay receiver. Two people work on this repo, each with their own Claude Code session (some run in the cloud on Linux and can't run the Windows overlay; real-screen testing happens on the Windows PCs).

## Working together (every session follows this)
1. At the start: `git checkout main && git pull`, then read `TASKS.md`.
2. Claim a task before starting: move it to "In progress" in `TASKS.md` with your name and branch, commit only that edit to `main` and push it. If someone else already holds that task or area, pick another or ask.
3. Work on your own short branch, named `<name>/<task>` (e.g. `sam/ball-detection`). Never commit code directly to `main`, never force-push `main`, never rewrite shared history.
4. Only touch files you own: `TASKS.md` → "Who owns what" says which files belong to which person (Jartartarta: detector/precision; Codingchancer: overlay + simulator). Ask the user which of the two they are if it isn't clear. Need a change in the other person's files? Open a GitHub issue instead of editing them. Big moves — splitting or renaming files, reformatting — get their own task and the other person is told first.
5. Commit small, push often, and pull `main` into your branch regularly.
6. Before merging, run the checks below; all must pass.
7. Open a pull request, merge it within hours rather than days, then move the task to "Done" in `TASKS.md`.

## Hard rule
It is a **visual practice aid only**. Never add code that clicks, aims, moves the mouse, sends input, or takes shots in the game.

## Files
- `main.py` — entry point only (`python main.py`); re-exports every name from the modules below so `import main` keeps working. New code goes in the modules, not here.
- `detector.py` — area **detector**: table / ball / cue / aim / ghost detection, `detect`, `predict_shot`, path tracing. Pure OpenCV/numpy, no Qt.
- `ball_net.py` — area **detector**: neural-network ball proposals (proof of concept, **off** unless `POOL_OVERLAY_NN_BALLS` is set, see below). Runs `models/balls.onnx` (0.24 MB, 60k weights, trained on `fake_game` frames plus 489 real frames of the public CC BY 4.0 "8 ball detector" set, credited in the README) with OpenCV's `cv2.dnn`: no new app dependency (onnxruntime has no Python 3.15 wheel). Pure OpenCV/numpy.
- `train_ball_net.py` — area **detector**: `render` (synthetic table crops + exact ball centres to `outputs/nn/`, never in git; seeds from 1,000,000, so never the stress or sweep seeds), `import-real` (a COCO export of real screenshots, e.g. from Roboflow Universe, downloaded to `outputs/datasets/`: each frame scaled up 2.5x to mirror size, table cropped, labelled ball centres with no class; frames without a table or labels left out), `split-real` (regroups frames into scenes by ball layout so no game is in both train and test: public sets are recordings of a few games), `eval-real` (whole held-out frames through `detect()` per mode), `train` (`--real SPLIT --real-share .15 --init CHECKPOINT`: real crops mixed into each batch, class-less focal loss, no offsets; keeps the last epoch) and `export` (PyTorch, in the separate gitignored `.venv-train`, `requirements-train.txt`; DataLoader workers die on Windows with Python 3.15, so batches come from a plain `multiprocessing.Pool`), `eval`.
- `frame_collector.py` — area **detector**: saves frames from the mirror window while you play (picture only; a table found and the picture changed, at most one every 2 s) to `outputs/real/` for training; never committed.
- `capture.py` — area **overlay**: guide drawing (`paint_guide`, `GUIDE_ALPHA`, `GuideStyle`: colours/thickness/bounce, saved via QSettings; never add white/grey colours or raise the alpha), `render_guide_layer`, `remove_overlay`, `shown_layer` (which recent drawing a capture shows), DPI helpers.
- `overlay.py` — area **overlay** (window) / **simulator-ui** (control panel): `Overlay` guide window, `Control` panel, `CueTracker`, `grab_clean` + background `AnalysisTask` (capture, clean and analyse back to back off the window thread); `GuideStabilizer` keeps the drawn guide still while the shot is unchanged (tolerances from measured frame noise).
- `tracking.py` — area **overlay**: `ShotTracker` reuses the table and balls of the last full `detect` while they stay still and only re-runs `predict_shot` (live speed).
- `window_capture.py` — area **overlay**: `WindowCapture` copies the mirror window's own picture (no guide in it), `window_under` finds the mirror under the guide (known titles win). GDI objects made once per worker and released by `close` (issue #13).
- `analysis_process.py` — area **overlay**: capture + `ShotTracker` loop in its own process (`AnalysisProcess`); exits when the app is gone, even if killed.
- `pool_rules.py` — area **simulator-ui**: `EightBallGame` (turns, groups, fouls, ball in hand, win/lose), pure Python; the physics reports `first_contact`, `rail_after_contact`, `pocket_order` for it.
- `simulator_ui.py` — area **simulator-ui**: `ShotSimulator`, `SimCanvas`, `ScreenshotTester`.
- `pool_physics.py` — the simulator's approximate 2D physics: follow/draw/english with the sliding/rolling model; no swerve, squirt, throw, jump or 8-ball rules (the UI and README must keep saying so).
- `fake_game.py` — synthetic table renderer with exact truth (a test fixture, not a game). Balls are turned at random as the game's balls are (`Scene.turned`, default on; `turned=False` gives the old flat look: number up, straight band; `TURN_BALLS` off makes `random_scene` and `SimGame` flat, as the older test modules do in `setUpModule`; `stress_test.py --flat`): one number badge, mostly off-centre or hidden; a stripe is a belt round the ball. `sim_game` rolls them along their paths (`roll`).
- `stress_test.py` — random synthetic shots vs truth (`--count 300`, `--save-failures DIR`).
- `live_check.py` — runs the real app against the synthetic table window through UI Automation.
- `sim_game.py` / `play_test.py` — area **detector** (tests): headless 8-ball test game (physics + rules + synthetic frames with truth; `shot_stream` gives a whole shot as the mirror shows it) and the overlay checked on whole games.
- `shot_recorder.py` / `recorder_check.py` — area **detector**: logs real shots from the mirror window (slider % at release, cue/struck-ball tracks, where balls stopped; reads the picture only) to `outputs/shots/`, and its check on synthetic games (`--flat` for the old look). The struck ball rolls, so it is followed as a disc that differs from the cloth picture (`RollingFollower`; `cloth_picture`: the still frame with the balls and the game's drawing painted out, `game_graphics`), centred on its rim (`refine_ball_centre`; near a cushion only within 1 px of the disc); its start is found the same way in the first frames after the shot, once the guide is gone (`_struck_home`). After the shot balls are told apart by colour and solid/stripe (`ball_signature`: white along the edge, on one side or more; unsure in about a sixth), a ball under the stick in the still frame has no sure colour, and a ball that moved and was not detected afterwards is looked for by its colours (`find_missing_ball`) before it counts as potted.
- `tests/` — unit tests. Screenshot-based tests skip when `outputs/*.png` is missing. The real screenshots are deliberately NOT in git (public repo: Miniclip's image + a player profile) — never commit images from `outputs/`.
- `setup.bat` / `run.bat` — build `.venv` with the newest Python 3.15…3.11 and start the app. `.venv` is never committed.

## How the detector works (short)
- Table: four corner pockets (dark blobs next to cloth), cushion nose = pocket centre inset by `POCKET_TO_CUSHION`·span, then each edge snapped to the cushion→cloth brightness drop. One corner covered: three corners + that long side's middle pocket (`_three_corner_fit`). Both corners of a short side lit (the game rings pockets red, a small dark core; the real frame that came out 40 px short): the other two corners + both middle pockets, mirrored (`_short_side_fit`; middle pockets are smaller than corners and sit outside the corner rows). The snap only takes a step down (`_edge_is_step`: darkest level up to `EDGE_SIDE_SHARE`·width outside at least `EDGE_STEP_MIN` (5) above the cloth's level right after the drop, as on navy where the cushion is only 8-10 above the cloth; nothing brighter than the drop's top right after it); a thin bright line with cloth on both sides (the guide's own table border left in a capture, which then held the table there; the game's aim line, stick and cue ball along a cushion) is skipped, and "strong" is measured among the steps only. Cloth-colour fit is the fallback.
- Balls: Hough circles on a cloth-difference image and a grey image, refined to sub-pixel on the rim, rejected when the inside is mostly cloth. Of two object-ball circles closer than 0.9 radii the better rim stays (`drop_second_circles`: a second circle on a striped ball's white cap).
- Network proposals (`POOL_OVERLAY_NN_BALLS`, off by default; `only+trust` is the measured setting): `ball_net` looks at the table crop resized to 640x320 (ball radius ~10 px) and gives a heatmap of ball centres per class (cue, solid, 8, stripe) at 1/8 size with sub-cell offsets (6 ms on the CPU). `only` replaces the Hough circles with its peaks, `add` adds them, `trust` keeps a peak scoring >= `NN_TRUST` (0.6) that looks like cloth inside. Each peak is snapped onto the rim by `refine_circle` unless that moves it more than `NN_REFINE_REACH` (0.25 radii: the fit locked onto a shadow, the ghost ring or a neighbour, as on a ball the cloth's colour); all its circles get the median fitted size; no number-badge proposal within a radius of a network peak (a turned ball's badge is off-centre). Every later step (cloth test, stick filter, cue ball, stripe and white-cloth fits) is unchanged. Real test set (public screenshots, 218 frames from scenes never trained on, `eval-real`): balls found 94.5% -> 97.1%, false 108 -> 14, frames all right 128 -> 182. Synthetic, turned: sweep 2384 -> 2736/2850, near 1498 -> 1723/1900, stress 281 -> 287/300 (flat 2630 -> 2769, 1658 -> 1721, 291 -> 293); black 8 on black cloth missing in 181 -> 8 of 250 frames, purple 4 on purple 51 -> 2, racks 437 -> 541/570. Our own frames (`outputs/bad`, mirror resolution): centres as good as Hough's (1.0 px typical from the ball's dark outline, 2.6 px at the 90th percentile against 3.1), but balls under the real stick are missed (scores 0.1-0.2) and the stick's butt cap is seen as a ball; a cue ball against a cushion beside the ghost ring scores 0.93 but a later step in `find_balls` drops it. Hence off. Its own centres are 0.3 px on synthetic frames but ~1.5 px and biased upwards on real ones.
- A ball the colour of the cloth (purple 4 on purple) looks like cloth inside and its number is mostly turned away (one badge, the balls roll). It is kept by its highlight (`BallLook.cloth_coloured_ball`): at the spot where the frame's balls show theirs (`highlight_offset`: peak of their average brightness pattern; real frames upper left at about (-0.4, -0.45) radii), brighter than the rest of that circle, than the cloth around and than the cloth's own level there (`local_lightness` with the balls painted out: bare cloth between the lettering's strokes is no highlight), a spot rather than a line (the guide, the stick), its inside differing from the cloth, not the ghost ring (a thin guide-white stroke round it; real balls' outlines are tinted), 1.75 radii from other balls. Not in `ball_beside_ring` (the cue ball is white). No ball but the cue ball lies within 1.3 ghost radii of a found ghost (`GHOST_OVERLAP`).
- Cue ball = the white ball whose aim ray ends in Miniclip's hollow ghost-ball reticle. Aim = polar ray scan + sub-pixel ghost. A white candidate whose rim is coloured along a quarter of it or more (`coloured_rim_share`: a stripe turned end-on) is only taken when nothing else is left.
- Struck ball right next to the cue ball ("near" shots): the ghost ring lies on the cue ball and hides the ray. `find_ghost_ring` finds the ring anywhere (thin bright stroke between dark outlines all round, white, ~0.9 ball radii; fitted on its own stroke, 0.05 px); only the cue ball can overlap it (`ball_under_ring`; the struck ball, which the game's object line leaves, only touches it). A cue circle on the ring itself, or none, is found again with the ring painted out (`paint_out_ring`, `ball_beside_ring`). A ghost on the cue ball is placed on the ring in `_predict_paths`, and the aim there comes from the stick (`stick_direction_near`: its band of off-cloth shade behind the cue ball, else its Hough edges; 0.16 deg at the 95th percentile).
- Target = ball touching the ghost; object/cue lines are fitted on the game's own short white lines when visible (`game_line_direction`: first the narrow band through the ball with the most stroke pixels, then its principal axis; long runs along the table border, the cushion's lit edge, are cleared from the line mask by `_clear_border_runs`).
- White cloth: lines read as thin ridges between their dark outlines (`white_stroke_masks`); cue ball and stripes fitted on the lit-side rim dip (`_WhiteCloth`), away from the shadow direction the balls show. A cue ball circle finding rejected as cloth is taken back (`white_cloth_missed_balls`: lit-side rim, drop shadow, lit face, no ball within 3 radii).
- Grey cloth: lettering (one darker shade of the cloth) counts as cloth in the ball test, as on light cloths (not on the near-black Lucky Shot cloth). Light tinted cloths (beige, sky, yellow, lime): the cue ball is fitted where the cloth's tint begins on its lit side (`pale_cloth_cue_centre`).
- Stripes on pale cloths (white, light grey, beige, sky; `PALE_CLOTH_CHROMA`): fitted on the two opposite arcs where the coloured band meets the cloth (`stripe_centres`, after the stick filter; colour difference from the cloth, halfway crossing, consensus circle of the balls' radius with points on both sides). A ball the stick lies across keeps its centre; the struck ball is moved only when its circle is not a diameter from the ghost and the fit is. On other cloths the fit only marks the ball as confirmed for the stick filter.
- Light grey cloth: where 3% or more of the cloth passes the white test (`LIT_CLOTH_SHARE`), strokes must be 10 brighter than the cloth around them, as on white. The cue ball is fitted on its lit side where its shading meets the cloth's level (`pale_cloth_cue_centre` with `KNEE_RISE`), also with the ring painted out in near shots. Under the ring, a ball as white as a cue ball is the cue ball whatever lines leave it (`CUE_WHITE`); a short-ray "ghost" that fails the strict ring test is dropped when the ring lies on the cue ball (`SHORT_RAY`).

## Capture feedback (important)
The guide is visible in screenshots/screen shares (`WDA_NONE`). To stop it feeding back into detection, every stroke is drawn at ≤60% alpha and the exact rendered layer is un-blended from each capture (`remove_overlay`); the control panel is greyed out in captures; right after a repaint the screen may still show an older drawing, so the overlay keeps its recent drawings and `shown_layer` picks the one the capture really shows (no fixed wait). With window capture (the default when a mirror window is under the guide) the guide is not in the frames at all; screen capture + removal is the fallback. Any change to drawing must keep these working — test the detect → draw → capture loop, not just window visibility (`tests/test_aim_alignment_and_capture.py`). `POOL_OVERLAY_DEBUG_DIR` dumps capture/layer/cleaned frames.

## Known limits
- Struck ball nearly touching the cue ball: the aim comes from the stick; where no stick shows behind the cue ball (~a quarter, e.g. against a cushion) it comes from the cue ball's centre, only good to ~1 px (whole pixels, rim half hidden), so the aim can be degrees off; white and pale cloths (white, light grey, beige, sky) still fail a quarter to a third of these shots, mostly on the cue ball's position (light grey: the lit arc beside the ring and the struck ball is short, and the fit gives up).
- Pale cloths: a stripe against a cushion or packed beside others keeps its circle (up to ~0.5 radius off); ~1 in 100 stripes is never proposed by circle finding (e.g. on the table's lettering) and is missed. Miniclip's real stripes are drawn in 3D (curved bands, outlined): the band fit is checked on synthetic belts (turned balls), not yet on a real pale table.
- Balls the colour of the cloth are found by their highlight; checked on real frames only for false circles (none on the game's own drawing). No real frame yet shows such a ball with its number turned away. A cloth-coloured ball no circle is proposed for (the 8 on near-black cloth, mostly) is still missed.
- Shot recorder: on the break, a solid and a stripe of one colour can be swapped in the potted list (in the packed rack a stripe can show mostly white and colours mix with the neighbours; its tests leave the break's potted list out). The struck ball at a pocket's jaw or against a cushion can be followed 2-3 px off (its shadow on the jaw pulls the disc, and there the rim fit is not trusted).
- Balls boxed in inside a rack can be off by ~0.5 radius.
- The ball-proposal network (off) is trained on synthetic frames and a public set of low-resolution real recordings (few scenes, rarely a stick across a ball): it misses balls under the real cue stick and can fire on the stick's ornaments or, with a wrong table fit (balls not ~1.55% of the table width), on anything ball-sized. Own frames with the stick across balls (`frame_collector.py`, kept out of git) are the next step before it can be switched on.
- Table fit with three or more corner pockets lit or covered falls back to the cloth colour. A table border still in a capture exactly on a nose moves that edge 1-2.5 px inwards (unchanged; the guide is normally not in the frames).
- Not yet verified on a real live AirPlay mirror or at Windows display scaling other than 100%.
